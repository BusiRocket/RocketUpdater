# RocketUpdater Final Launchd-Safe Updater and Supervised Cleanup Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (- [ ]) syntax for tracking.

**Goal:** Make RocketUpdater safe and diagnosable under launchd, correct the existing updater defects, add only machine-verified update/report plugins, and move all deletion into a separately invoked, supervised `--clean` command.

**Architecture:** The parent runner owns locking, preflight, static metadata validation, timeouts, result aggregation, and structured events. Metadata is parsed from literal headers without executing plugin code. Every plugin is sourced exactly once and executed inside a separate Bash child process so it cannot change the parent shell. `--scheduled` updates and reports but never deletes. A manual TTY-only `--clean` path exposes three guarded operations whose bytes are locally proven reconstructable or obsolete: Homebrew cache/temp cleanup, public-registry npm cache cleanup, and obsolete stopped-app ChatGPT Sparkle installations. Other irreversible one-offs live in TODO.md. launchd invokes the updater path with a deterministic environment and a least-privilege sudoers rule for one exact download-only `softwareupdate` command.

**Tech Stack:** macOS 26.6.2, Apple Silicon, /bin/bash 3.2, BSD userland, Homebrew 6.0.20, GNU coreutils timeout 9.11, native /usr/bin/lockf, launchd, newsyslog, shellcheck, shfmt.

## Global Constraints

- Nothing is scheduled until Phase 0 passes.
- Unattended deletion is denied without exceptions. `--scheduled` must have zero reachable removal, prune, purge, clear-cache, or truncation calls.
- Manual cleanup is also default-deny. Its only initial allowlist is guarded Homebrew cache/temp cleanup, guarded public-registry npm cache cleanup, and verified obsolete stopped-app ChatGPT Sparkle installations. It does not include Docker objects/build cache, Yarn metadata, Cargo sources, OpenClaw logs, Whisper models, Composer backups, Deno/PlatformIO/Bun caches, npx cache, or broad Mole/macOS cleanup.
- `--clean` requires real TTY stdin/stdout, refuses `NONINTERACTIVE=1` and `ROCKETUPDATER_LAUNCHD=1`, prints exact candidates and allocated KiB, and requires the user to type the operation name. It never runs as a side effect of default or scheduled updating.
- Code, comments, identifiers, documentation, commits, PR text, and generated artifacts are English.
- Use the existing Git identity and no assistant attribution or co-author trailer.
- One exported unit and one responsibility per file; dependencies are explicit.
- Preserve Bash 3.2 compatibility. Do not use associative arrays, mapfile, coproc, or Bash 4 syntax.
- Every plugin receives no stdin.
- Every external operation has a bounded timeout and a truthful exit status.
- Never print credential values. Logs may contain command output, so create them with mode 0600.
- All shell changes must pass ./scripts/format.sh --check and ./scripts/lint.sh.
- Do not edit an existing migration file; none is in scope.

## Discovery Summary

- RocketUpdater.sh globally enables set -e, sources plugins into the parent, and has no timeout or isolation boundary.
- The summary aggregates ordinary nonzero function returns, but a sourced plugin can exit, alter traps/options/cwd, or hang forever before aggregation.
- The current no-TTY sudo path probes sudo -n true. That cannot use the proposed command-specific NOPASSWD rule.
- The proposed launchd PATH omits /Users/cristiandeluxe/.cargo/bin and /Users/cristiandeluxe/go/bin.
- /opt/homebrew/bin/flock is absent; native /usr/bin/lockf is present and designed for this job.
- Docker already has a docker info gate. Its real defect is that every prune failure is suppressed and the body is destructive.
- softwareupdate supports -d -r; --include-config-data is absent; --background is broader than download-only.
- The machine has no Time Machine destination. That raises the bar for every destructive action.
- The measured cleanup baseline and every final disposition are reproduced below; this plan does not depend on the audit files for execution.

## Target Outcome

- Manual and scheduled runs cannot overlap.
- A plugin cannot terminate, poison, or block the parent runner.
- Exit status 0 means all selected plugins succeeded or were intentionally skipped; nonzero names every failure. Disabled selected plugins count in total and skipped; the success text says “No plugin failures,” never “All updates completed.”
- Exit status 20 from a plugin means skipped, 124 means timed out, 75 means lock contention, and 78 means invalid configuration/preflight.
- Scheduled mode reaches no deletion. It never runs Docker removal/prune, Mole clean, Yarn metadata deletion, Cargo source deletion, OpenClaw truncation, model deletion, or any cache cleanup.
- Manual `--clean` reaches only `guard_homebrew_cleanup`, `guard_npm_public_cache`, and `guard_sparkle_obsolete_installations`; every guard fails closed before deletion.
- A structured 0600 event log records run_id, timestamp, level, event, plugin, status, duration_seconds, and message.
- A fixed, minimal PATH reaches every selected binary on this Mac.
- The only unattended privilege is /usr/sbin/softwareupdate -d -r.

## Interface Design Decision

Two designs were considered because Phase 0 changes the plugin execution interface.

### Design A — keep sourced functions in the parent and add a watchdog

- Depth: small initial diff.
- Locality: timeout, traps, counters, cwd restoration, and shell-option restoration are scattered through the parent.
- Seam: weak; exit and trap changes can still terminate or corrupt the runner, and descendant cleanup is unreliable.

### Design B — static metadata parser plus isolated plugin child

- Depth: adds one non-evaluating metadata reader and one plugin-entrypoint script.
- Locality: the parent owns orchestration; the child owns plugin loading/execution; timeout owns the child process group.
- Seam: strong; only metadata text and an integer status cross the boundary.

**Decision:** use Design B. It is the smallest design that fixes exit, set-e, trap, cwd, function-collision, timeout, and aggregation failures together.

~~~sh
#!/bin/bash

PLUGIN_NAME="Sparkle Feed Inventory"
PLUGIN_VERSION="1.0.0"
DISABLE=false
PLUGIN_PRIORITY=60
PLUGIN_TIMEOUT_SECONDS=900
PLUGIN_SCHEDULE_ACTION=run

update_sparkledrift() {
    if ! command_exists curl || [ ! -x /usr/libexec/PlistBuddy ]; then
        echo_skip "curl or PlistBuddy is unavailable"
        return 20
    fi

    local app_path
    for app_path in /Applications/*.app /Applications/*/*.app "$HOME"/Applications/*.app; do
        [ -d "$app_path" ] || continue

        local feed_url
        feed_url=$(/usr/libexec/PlistBuddy -c "Print :SUFeedURL" \
            "$app_path/Contents/Info.plist" 2>/dev/null) || continue

        local app_name
        app_name=$(basename "$app_path")

        case "$feed_url" in
        https://*) ;;
        *)
            printf 'sparkle app=%s status=unsupported-feed\n' "$app_name"
            continue
            ;;
        esac

        local local_version
        local_version=$(/usr/libexec/PlistBuddy -c "Print :CFBundleShortVersionString" \
            "$app_path/Contents/Info.plist" 2>/dev/null) || local_version="unknown"

        local appcast
        if ! appcast=$(curl -fsL --connect-timeout 5 --max-time 20 \
            --proto '=https' "$feed_url" 2>/dev/null); then
            printf 'sparkle app=%s local=%s status=unreachable\n' \
                "$app_name" "$local_version"
            continue
        fi

        local feed_version
        feed_version=$(printf '%s' "$appcast" |
            sed -n 's/.*sparkle:shortVersionString="\([^"]*\)".*/\1/p; s/.*<sparkle:shortVersionString>\([^<]*\)<.*/\1/p' |
            head -1)
        if [ -z "$feed_version" ]; then
            feed_version=$(printf '%s' "$appcast" |
                sed -n 's/.*sparkle:version="\([^"]*\)".*/\1/p' |
                head -1)
        fi
        if [ -z "$feed_version" ]; then
            feed_version="unparsed"
        fi

        printf 'sparkle app=%s local=%s feed_first=%s status=observed\n' \
            "$app_name" "$local_version" "$feed_version"
    done

    echo_warning "Feed versions are evidence only; channel and ordering are not authoritative"
    return 0
}
~~~
